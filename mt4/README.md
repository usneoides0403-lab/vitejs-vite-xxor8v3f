# IG Client Sentiment Gauge (MT4)

IGの Client Sentiment API（ロング/ショートの建玉比率）をMT4のチャート上にパネル表示します。
コントラリアン（逆張り）指標としての利用を想定しています。

## 構成

| ファイル | 置き場所 | 役割 |
| --- | --- | --- |
| `MQL4/Experts/IG_ClientSentiment_Feeder.mq4` | `MQL4\Experts\` | IG APIへのログインとセンチメント取得。結果を端末のグローバル変数へ公開 |
| `MQL4/Indicators/IG_ClientSentiment_Gauge.mq4` | `MQL4\Indicators\` | グローバル変数を読んでチャートにパネル描画 |
| `MQL4/Include/IGSentiment/IGSentiment.mqh` | `MQL4\Include\IGSentiment\` | 両者の共有定義（変数名・ステータスコード） |

### なぜ2つに分かれているのか

MT4のインジケーターからは `WebRequest()` を呼べません（インジケーターはUIスレッドで実行されるため、
ブロッキングする通信関数が禁止されています）。単一のインジケーターでHTTPを叩こうとすると
`WebRequest()` は常に `-1` を返し、データが永久に取得できません。

そのため通信はEA（フィーダー）が担当し、取得結果を端末のグローバル変数に載せて
インジケーター（表示）に渡す構成にしています。

## セットアップ手順

1. **IG APIキー取得**
   My IG → 設定 → API keys（デモ口座で無料開設可、資金不要）

2. **WebRequest許可**
   MT4の ツール → オプション → エキスパートアドバイザー →「WebRequestを許可するURL」に
   以下を追加します。
   - `https://demo-api.ig.com`
   - `https://api.ig.com`

3. **ファイル配置**
   ファイル → データフォルダを開く → `MQL4` 配下に上表のとおり配置し、MetaEditorでコンパイル。

4. **フィーダーEAをチャートにアタッチ**
   任意のチャート1枚に `IG_ClientSentiment_Feeder` をアタッチし、ID / パスワード / APIキーを設定。
   「自動売買を許可する」をONにしてください（EAのタイマーを動かすために必要。売買注文は一切出しません）。

5. **インジケーターをチャートにアタッチ**
   表示したいチャートに `IG_ClientSentiment_Gauge` をアタッチ。
   `InpMarketIdOverride` はフィーダー側と必ず同じ値にしてください（両方空欄なら自動判定同士で一致します）。

同じ `marketId` を複数チャートで表示する場合、フィーダーEAは1つだけ動かせば足ります。
逆に別々の `marketId` を見たい場合は、その数だけフィーダーEAを別チャートにアタッチしてください。

## 認証情報の扱い

EAの入力欄に入れたパスワードは平文で保存され、`.set` / `.chr` ファイルにも残ります。
**専用のデモ口座を使うことを強く推奨します。**

チャート設定に残したくない場合は、`InpCredentialsFile` に `MQL4\Files` 配下のファイル名を指定すると
そちらから読み込みます（入力欄の3項目より優先）。書式:

```
# ig_credentials.txt
identifier=your_ig_login_id
password=your_password
apikey=your_api_key
```

このファイル自体も平文である点は変わりません。テンプレートやセットファイルを他人に渡すときに
資格情報が同梱されない、という程度の利点です。

## パラメータ

### フィーダーEA

| パラメータ | 既定値 | 説明 |
| --- | --- | --- |
| `InpIGUsername` / `InpIGPassword` / `InpIGApiKey` | - | IGの認証情報 |
| `InpCredentialsFile` | 空 | `MQL4\Files` 内の認証情報ファイル名（指定時は上記より優先） |
| `InpUseDemo` | `true` | `false` で本番API |
| `InpMarketIdOverride` | 空 | 空欄なら通貨ペアのシンボル先頭6文字から自動判定（EURUSD等） |
| `InpRefreshMinutes` | `15` | 更新間隔（分）。最短60秒にクランプされます |
| `InpVerboseLog` | `false` | APIの応答本文をログ出力 |

### インジケーター

| パラメータ | 既定値 | 説明 |
| --- | --- | --- |
| `InpMarketIdOverride` | 空 | フィーダーと揃えること |
| `InpWarnThreshold` | `65.0` | この%を超えたら逆張り警戒色に変える |
| `InpStaleMinutes` | `45` | 最終更新がこれより古ければグレー＋「(古いデータ)」表示 |
| `InpLongColor` / `InpShortColor` / `InpBgColor` | - | 配色 |
| `InpPanelX` / `InpPanelY` / `InpCorner` | - | パネル位置。四隅いずれでもレイアウトは崩れません |

## marketId について

`marketId` はシンボル先頭6文字から自動判定します（`EURUSD.a` → `EURUSD`）。
ブローカーのシンボルが特殊な場合や、指数・商品のセンチメントを見たい場合は
`InpMarketIdOverride` で手動指定してください（例: `US500`, `GOLD`）。
指定が誤っているとステータス行に「応答の解析に失敗: marketIdを確認してください」と表示されます。

## ステータス表示

パネル最下段に状態が出ます。

| 表示 | 意味 |
| --- | --- |
| `更新: yyyy.mm.dd hh:mm` | 正常。最終取得時刻 |
| `取得待ち...` | フィーダー起動直後、初回取得前 |
| `フィーダーEAが動作していません` | 3分以上フィーダーの心拍が更新されていない |
| `通信失敗: MT4のURL許可リストを確認してください` | `WebRequest()` が `-1`。手順2を確認 |
| `ログイン失敗: ID/パスワード/APIキーを確認してください` | 認証エラー（デモ/本番の取り違えも要確認） |
| `取得失敗 HTTP=nnn` | APIがエラー応答。詳細はエキスパートログ |
| `応答の解析に失敗: marketIdを確認してください` | エンドポイントは応答したが期待するフィールドが無い |

## 注意

- IG側のセンチメントデータ自体の更新頻度はそれほど高くないため、既定の15分間隔で十分です。
- IGのAPIにはレート制限があります。更新間隔を極端に短くしないでください。
- 表示は建玉比率であり、売買シグナルではありません。閾値超え＝逆張りエントリー、という単純な話ではない点に留意してください。

## 価格帯別の分布(オーダーブック)について

「どの価格帯にポジションが集中しているか」まで見るには、比率だけを返すIGのAPIでは不足です。
その用途で有力なのはOANDAのOrder Book / Position Book APIですが、日本居住者が使うOANDA証券
(oanda.jp)のAPIはGOLD会員限定で、**本番口座を開設・入金し、本番用トークンを発行して初めて
デモ用トークンが解放される**仕組みになっており、デモ環境だけでは着手できません
（グローバル版のOANDA Corporation/oanda.comとは別法人・別ルールです）。

このため本ツールは価格帯分布には対応せず、IGの比率表示のみとしています。
価格帯分布が必要になった場合は、本番口座開設後にOANDA証券のAPI利用規約とエンドポイント仕様
（v20互換かどうか含む）を改めて確認してください。
